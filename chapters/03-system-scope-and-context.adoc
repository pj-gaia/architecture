= System Scope and Context

System scope and context delimits the system (Project Gaia) from all communication partners (neighbouring systems and users).
It specifies the external interfaces.

== Business Context

Project Gaia sits at the intersection of the development workflow and the compliance/release process.
It acts as an integration hub: consuming data produced by engineering tools and presenting a unified view to both engineers and product stakeholders.

.External actors and systems
[cols="2,2,4", options="header"]
|===
| Actor / System | Direction | Description

| Engineer
| ↔ Gaia
| Interacts with the platform to review quality gate status, SBOM data, and vulnerability findings for their product components.

| Product Manager
| ↔ Gaia
| Audits release quality and compliance posture via consolidated dashboards or reports.

| Quality Manager
| ↔ Gaia
| Verifies that release candidates satisfy internal quality requirements and evidence is complete.

| Compliance Officer
| ↔ Gaia
| Reviews policy conformance and risk posture based on consolidated artefacts and findings.

| Pipelines
| → Gaia
| Provides build and release events and delivers generated analysis artefacts for evaluation.

| SAST Tools
| → Gaia
| Contributes static analysis findings that are correlated with product and release context.

| Software Composition Analysis Tools
| → Gaia
| Supplies software composition analysis evidence, including SBOM artefacts (for example CycloneDX or SPDX) and vulnerability intelligence used to assess component risk.
|===

.Technical interfaces
[cols="2,2,2,3", options="header"]
|===
| Interface | Protocol | Data Format | Notes

| User web application
| HTTPS / REST
| HTML, CSS, JavaScript, JSON
| Used by Engineer, Product Manager, Quality Manager, and Compliance Officer to review status and evidence.

| Pipeline integration endpoint
| HTTPS / Webhook
| JSON
| Receives build/release events and references to generated artefacts.

| SAST tool integration
| HTTPS / REST
| JSON (findings payload)
| Tool-specific authentication (API token/OAuth2) and source signature validation where supported.

| SCA tool integration
| HTTPS / REST or Webhook
| CycloneDX or SPDX (JSON/XML), JSON
| Receives software composition analysis data, including SBOM documents and vulnerability information, from integrated SCA tooling.
|===
